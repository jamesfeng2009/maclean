对 src/ 29,497 行做了一次完整逻辑 review。核心链路自己读，scanner/安全/UI 三路并行派 agent 深挖，**所有 P0 结论均亲自读码或本机实测确认**。

### 发现的 P0（6 条）
1. **概览「一键清理」是空操作**（ui/mod.rs:5073-5083）：调 `prepare_delete()` 走 `tab_index()=0`，`results[0]` 恒空 → 静默 return。而 `app.rs:965` 的 `prepare_delete_cross_tab()` 已实现却**全仓无调用点**。修复：改调 cross_tab 版本。
2. **Touch ID 删除必卡死**（ui/mod.rs:462-489）：`NeedPassword` 分支末尾 `clear_delete_rx = true; break;` 无条件执行，把分支内刚创建的 receiver 当帧丢弃 → confirm 永停 SudoWithTouchId。同文件 :551 注释显示这是历史 bug 复发。
3. **跨 Tab 确认框显示 0 项 0 B**（ui/mod.rs:2940-2977）：统计按 `tab_index()` 而非 `pending_delete`，标题"确认删除 0 项"但实际真删 N 个文件，且 `needs_admin` 漏判导致该提权不提权。
4. **bundle ID 未校验拼路径**（scanner/uninstall.rs:855）：`home.join(format!("Library/Containers/{}", bid))`，bid 来自 `defaults read CFBundleIdentifier` 原始输出。构造 `../../../../Users/xxx/Documents` 可让整个 Documents 被列为关联数据；safety 第 4a 层只精确匹配（允许删子项）拦不住。
5. **safety.rs:74「 | 」早退**：`path.contains(" | ")` 在全部黑名单之前无条件 `return Safe`，`/System/Library | x` 直接放行。本意是放 APFS 快照，应收紧为 `starts_with("com.apple.TimeMachine.") && contains(" | ")` 并移到黑名单之后。
6. **license 后门**（license.rs:33-37）：`is_dev_mode()` 无 cfg/feature 门控，`MACLEAN_DEV=1` 在 release 二进制里直接 Activated 且免额度。

### 重要：推翻一条 agent 误报
「APFS 大小写绕过 /system」**不成立**。本机实测 `realpath(/system) = /System`、`realpath(/system/library) = /System/Library`、`realpath(//System/Library) = /System/Library`，canonicalize 会归一化大小写，第 3 层 `starts_with("/System/")` 仍命中。**教训：安全类结论必须实测，不能靠推断。**

### 未实测（待复现，Windows 上若成立是灾难级）
`scanner/windows_apps.rs:3316/3501/3247/3269` 双向子串匹配：卸载 "Microsoft Edge" 生成 "microsoft" → 可能匹配 `HKCU\SOFTWARE\Microsoft` 并执行 `reg delete /f`；短名应用 "Go"/"R" 会 `contains` 命中 `%APPDATA%\Google` → 删 Chrome 用户数据。

### 方法论补充（两条踩过的坑）
1. **内部纯函数的单测可能是假覆盖。** #15 一开始只测 `homes_from()`，绕过了真正的组合点（`protected_homes` 要不要传 real）——回退修复后测试照样通过。必须让被测者的**调用面**和线上一致，或把注入口开在真正做决策的那一层。
2. **插辅函数会截碎别人的文档注释。** safety.rs 里在 `fn xxx` 锚点前插入 helper，结果把 `check_path_safety_with_category` 的 doc 块拦腰截断（靠 clippy `doc_lazy_continuation` / `empty_line_after_doc_comments` 才暴露）。修法：把 helper 插到目标 doc 块的**起始之前**，不要插在 doc 与 fn 之间。

### 方法论沉淀（Windows-only 代码怎么测）
1. **不加 cfg 的跨平台纯函数**：在 macOS 开发机上跑 Windows 规则测试。
   `is_windows_critical_path` / `extract_reg_value` / `jetbrains_roots` /
   `build_uac_delete_script` 都是故意不限 cfg 才测得动的。
2. **只测纯函数可能是假覆盖**：本次反向验证再次印证 —— 回退修复后，
   直接调 `is_windows_critical_path` 的用例仍然全绿，**只有走入口
   `is_critical_system_path` 的那条才 FAILED**。必须有一条端到端接入点用例。
3. **测试里 Windows 路径要写正斜杠**（`C:/Users/Bob`）：macOS 下 `\` 不是分隔符，
   整条路径会被当成一个组件，`Path::starts_with` 必然失效，写成 `\` 的用例是假绿。
4. **脚本/命令构造要抽出来测**：UAC 删除脚本的转义（`' → ''`）、`-LiteralPath`
   （避免 `[]` 被当通配符）、结果行协议都用单测锁住。
5. **源码级一致性检查**：对 cfg(windows) 编译不到的执行器，用 `include_str!` 检查
   "清单里的任务名是否都有执行分支"，能拦住"UI 列出按钮但点了没反应"。
