   、`:3476 delete_registry_residual`（`reg delete /f`）内部都没有任何校验，

   **关键坑**：X-5 的 `is_deletable_reg_path` 要求 SOFTWARE 下深度 ≥3，
   但 `scan_registry_residual` 产出的合法目标就是 SOFTWARE 下一级键
   （如 `HKCU\SOFTWARE\Zoom`）。照搬会让所有注册表残留删除失效，
   必须分两档，且改动后 Windows 上「什么能删」会变，须真机回归。→ Task #34

**#33** `cmd_clean` 现在复用 ops 的二次校验；顺带把 `sanitize_for_sudo`
改名为 `sanitize_before_delete`（CLI 也用，名字里的 sudo 会误导）。
反向验证时发现一个意外保护：把删除循环改成遍历未校验列表会因为 move
语义**编译不过**，Rust 的借用检查顺手挡住了这条回退路。

**#34** 分两档是关键：`is_deletable_reg_key_basic`（只挡形状，放行
`SOFTWARE` 一级子键）vs `is_deletable_reg_path`（深度 ≥3 + 末段带版本号，
只服务版本化下钻）。照搬严格的会让整个注册表残留清理静默失效。

**#37 推翻了此前假设**：simctl 用 **1024** 不是 1000。用 `simctl runtime
list -j` 的 `sizeBytes` 精确总和 26,371,017,423 对照 `24.6G`：1024³ 偏差
-0.16%，1000³ 偏差 +7.2%。真正的 bug 是解析取错行——取"第一个括号"拿到
build 号 `22F77`，`parse_size_str` 对未知单位回落 1.0，24.6G 被算成
**22 字节**。两处修复互相独立（回退任一仍被另一处兜住，需同时回退才红）。

### 方法论沉淀更新

`~/.workbuddy/skills/crossplatform-deletion-safety/` 需补一条：
「纯函数的闸门 ≠ 生效的闸门」。本轮 X-5 自己就踩了 —— `is_deletable_reg_path`
测得很全，但它没接进真正的删除出口。判定要问的是「这个 true/false 最终
拦在哪一次系统调用之前」，不是「这条规则有没有测试」。
